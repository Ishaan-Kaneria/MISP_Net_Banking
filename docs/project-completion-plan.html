Executive Summary

Arth-AI is a working hackathon vertical slice for hyper-personalized banking in Bharat. The repository contains a FastAPI backend, Next.js PWA, PostgreSQL/pgvector Docker stack, seeded personas, fraud scoring, life-stage classification, ethics rules, chat fallback, mock KYC, explainability, and a judge-facing transaction simulator.

The project is not yet submission-complete because the full stack has not been run on a machine with Node.js and Docker, and several production-grade requirements remain to be implemented or verified. The next milestone is runtime validation, followed by targeted completion of the missing architecture and quality gates.

Already Implemented

Backend and API

  • FastAPI service, CORS, health endpoint, JWT login, seeded users, mock KYC and consent.
  • SQLAlchemy models for users, accounts, transactions, features, scores, recommendations, alerts, audits, KYC, chat messages, and policy documents.
  • Mock ledger, required API routes, Alembic environment, initial schema migration, and Docker migration startup.

Fraud, ML, and Ethics

  • Merchant classification, India-time night detection, geo-jump, new-device, velocity, watchlist, and high-value rules.
  • IsolationForest anomaly scoring on synthetic normal data.
  • XGBoost life-stage classifier with fallback: FIRST_JOB, MARRIAGE, MEDICAL, STRESS, SAVER, HIGH_VELOCITY, BASELINE.
  • Stress detection, ethics gate, SIP, insurance, EMI conversion, starter credit, and grace-period recommendations.

Chat and RAG

  • Persistent chat messages, policy corpus, lightweight retrieval, retrieval traces, optional Gemini integration, and safe fallback.

Frontend and Demo

  • Next.js mobile-first PWA with login, KYC, dashboard, balance, activity, offers, alerts, chat, auditor view, and transaction simulator.
  • Dockerfiles, Compose configuration, manifest, environment examples, ignore files, and focused tests.

Required Before Calling It Complete

Priority 0: Runtime Setup and Smoke Test

  1. Install Node.js 20 LTS and Docker Desktop.
  2. Run git pull origin main.
  3. Run docker compose up --build.
  4. Verify the frontend, /health, /docs, login, KYC, dashboard, chat, explainability, and simulator.

Priority 1: Fix Runtime Failures

Resolve actual issues from the first run: PostgreSQL timing, Alembic/pgvector behavior, XGBoost installation, CORS, mobile layout, balance invariants, and seed idempotency.

Priority 2: Complete Data and ML Contracts

  1. Add VECTOR(768), pgvector extension, cosine indexes, embedding generation, and vector retrieval.
  2. Add offline training that generates at least 2,000 users and 80,000 synthetic transactions.
  3. Persist and version IsolationForest and XGBoost artifacts.

Priority 3: Complete Chat Tools

Implement server-side balance, offers, recent-transactions, and restructure tools. Ensure the model cannot write directly to the database, stressed users receive grace support only, and sensitive identity data never reaches the LLM.

Priority 4: Security Hardening

  • Consistent error contracts, transaction limits, balance invariants, rate limiting, secret validation, structured logging, admin authorization, and ownership checks.

Priority 5: Testing

Add API, seed, balance, fraud, ethics, explainability, chat fallback, Gemini timeout, Alembic, frontend build, and browser smoke tests.

Priority 6: Submission Polish

Add a judge walkthrough, audit table, transaction details, real language switching, loading/error states, accessibility, PWA icons, responsive checks, and a final demo script.

Definition of Done

  • Compose starts database, API, and frontend without manual fixes.
  • Alembic creates the complete schema on a clean database.
  • All required routes and five demo stories work.
  • Fraud blocks the high-risk scenario before balance debit.
  • Stressed users receive grace support and no active personal-loan offer.
  • Chat is policy-grounded, persisted, and safe with or without Gemini.
  • Backend tests, browser tests, and frontend production build pass.
  • No secrets or real identity data are committed.
  • A judge can run the demo from the README alone.
